# M3 苔の計画

版: 0.2(2026-11-20)/状態: 作者の判断を反映。段階 A1 の前

M3 では、ウィンドウ情報のサービスと苔を作り、v0.3 にする(SPEC 7 章)。完了の条件は 2 つある。SPEC 4.3 の受け入れ基準を作者が目で見て通すことと、苔を足す差分に NagiCore と NagiKit の変更が無いことである。M2 と同じく、コアを先に作って固め、苔はそのあとでパッケージとして足す。

計画は Claude と Codex がそれぞれ独立に作り、突き合わせて 1 つにした。アドバイザーにも相談した。どちらの案から何を採ったかは 8 章に書く。

## 1. 前提

### 1.1 M2 から引き継ぐもの

- `Capability.windows` は宣言だけしてあり、中身はまだ無い。`FrameState.displays`(デスクトップの pt、左上が原点)は M2 で入れた
- 合成の順は `.surface → .light → .glass` で、苔は一番下に入る。木漏れ日は苔の上に落ち、雨は苔と木漏れ日をまとめて屈折させる。苔のためにコアの合成を変える必要はない
- 性能の余裕は小さい。木漏れ日と本降りの雨で、1 フレームの GPU の時間の 95 % 点は 13〜14.9 ms だった(M2-LOG)。16.7 ms までの余裕は約 1.8 ms しかない
- 設定の既定(`defaultEnabled`)は、許可の要らないエフェクトをオンにする。このままだと、苔を登録しただけで、新しく入れた人と、エフェクトの一覧を一度も切り替えていない人の苔がオンになる

### 1.2 2026-11-20 に確かめたこと

開発機(5K の Studio Display 1 台、2560 × 1440 pt)で、`CGWindowListCopyWindowInfo` が返すウィンドウの層、矩形、α、画面に出ているかを読んだ。名前は読んでいない。

- 画面に出ているもの(`.optionOnScreenOnly`)は 11 枚で、層 0 が 9 枚、層 24 が 1 枚(メニューバー、高さ 30 pt)、層 20 が 1 枚だった。層 20 は**画面全体(2560 × 1440)を覆う**ウィンドウで、Dock と見られる。「通常より上の層はすべて手前を覆う」と決めると、このウィンドウが画面のすべての苔を消す
- 層 0 にも α 0.9 のウィンドウがあった
- `.optionAll` では 142 枚が返り、画面に出ていないウィンドウ(最小化、別の Space など)も矩形付きで載った。こちらで追えば、Space を切り替えてもウィンドウの記録が切れない
- 1 回の取得は、最初が 73 ms、`.optionAll` が 10.6 ms だった(1 回ずつの測定)
- ウィンドウの矩形は左上が原点の pt で、`FrameState.displays` と同じ座標だった(ディスプレイ 1 台で確かめた)

## 3. ウィンドウ情報のサービス(SPEC 3.10)

### 3.1 NagiKit に足すもの

`FrameState.windows: WindowSnapshot?` を足す。`.windows` を求めないエフェクトと、まだ取得できていないときは `nil` にする(空の配列は「取得できて、対象が 0 枚」)。

| 値 | 意味 |
|---|---|
| `frontToBack: [WindowInfo]` | 手前から順。配列の順が前後の順で、別の番号は持たない |
| `layoutRevision` | ウィンドウの ID・矩形・順序・役割か、ディスプレイの構成が変わると増える。時間が経っただけでは変わらない。苔が形を作り直すかどうかの判断に使う |
| `usableAreas: [CGRect]` | ディスプレイごとの、メニューバーと Dock を除いた範囲(`NSScreen.visibleFrame` をデスクトップの pt にしたもの)。画面の下の隅の苔を Dock の外に置くために使う |
| `desktopSeconds` | ディスプレイの構成が変わらずに続いている秒数。画面の下の隅の苔の年齢 |
| `WindowInfo.id`、`frame` | ウィンドウの番号と、デスクトップの pt の矩形 |
| `WindowInfo.role` | `.surface`(苔が生え、手前も覆う)か `.occluder`(覆うだけ) |
| `WindowInfo.stationarySeconds` | いまの矩形のまま続いている秒数 |

ウィンドウのタイトル、アプリ名、PID は渡さない(SPEC 5 章)。所属するディスプレイは `frame` と `displays` から求まるので持たない。固める前に、どの値も試験用のエフェクトで使うことを確かめる。使わない値は入れない。

### 3.2 役割の決め方

- 自分のプロセスのウィンドウは除く。除き損ねると、全画面のオーバーレイがすべての苔を隠す
- 層 0 で、120 × 60 pt 以上、α が 0 より大きいものは `.surface`
- 層 0 でも、ディスプレイ全体を覆うもの(全画面のアプリ、ぴったりの最大化)は `.occluder` にする。全画面の本文や映像の上辺に苔を出さないため
- 層 0 の小さいものと、層 1 以上のもの(メニューバー、開いたメニュー、浮かぶパネル)は `.occluder`。ただし、層 1 以上でディスプレイ全体を覆うもの(1.2 の層 20)は除く。中身の形が分からず、残すとすべてを隠すため
- 半透明のウィンドウも、矩形の内側は覆うものとして扱う

### 3.3 「最後に動いてから」の数え方

- 矩形のどれかの辺が、基準の矩形から 1 pt を超えて変わったら 0 に戻す。基準は最後に確定した矩形に固定する(少しずつ動き続けるウィンドウも、合計が 1 pt を超えた時点で分かる)。前に出しただけ(順序の変化)は動いたに数えない
- 記録は ID と PID をキーにしてメモリに持つ。`.optionAll` で取るので、最小化や別の Space で画面から消えたウィンドウも記録が続く。一覧から消えたら記録を捨て、同じ番号が後で出ても初見として扱う
- 次に取れたとき、ID・PID・矩形が同じなら続いていたとみなす。ロック、スクリーンセーバー、ディスプレイのスリープ、Mac のスリープでも捨てない(スクリーンセーバーとディスプレイのスリープでも `screenIsLocked` が届くので、ロックで捨てると 2 時間はめったに貯まらない)
- 時計は、Mac のスリープ中も進む `ContinuousClock` を使う案と、止まる `SuspendingClock` を使う案がある。前者なら、夜のあいだ置いたウィンドウに朝は育った苔がある(7 章で作者が決める)。壁時計は使わない(時計を合わせたときに年齢が跳ぶため)
- Nagi を起動し直したら、すべて 0 から始める。ID と時刻はファイルに書かない
- 実画面の確かめのために、年齢を何倍にも進める試験用の起動オプション(例: `--debug-window-age-scale 60`。10 分が 10 秒、2 時間が 2 分になる)を A2 で入れる。これが無いと、起動し直すたびに年齢が 0 に戻るので、区切り J と K を実画面で見られない

### 3.4 取得の頻度

- 取得は専用の直列のキューで行い、描画のスレッドは待たない。渡すのは最新のスナップショット 1 つだけで、取得の途中で止めたものの結果は捨てる(M2 の取り込みと同じ番号の付け方)
- 活動中: `.windows` を求めるエフェクトがオンのときだけ、30 秒おきに取る。動いたウィンドウは次の取得で矩形が違うので、間隔で変わるのは「いつ動いたか」の精度だけで、10 分〜2 時間の成長には 30 秒で足りる。SPEC 3.10 の「数秒おき【仮】」を変えるので DECISIONS に残す。凪の判定ですでに起きる時刻があれば、それに相乗りする
- 凪に入るとき: 新しい取得が届いてから苔を出す。活動中に取った古い矩形で最初のフレームを描かない
- 凪の間: 2・5・15 Hz を A2 で測って決める。凪の間に変わるのはアプリが自分で開いたウィンドウぐらいで、1 回 10 ms なら 15 Hz で 1 コアの 15 % ほどを使う(雨の CPU 約 25 % に重なる)
- ロック、スリープ、抑止のあいだは取得を止める

### 3.5 見本の配置(`nagi-render` とギャラリー)

- 見本の配置を JSON(基準のディスプレイの大きさと、手前から順の `{id, rect, role, age}`)で書き、`nagi-render --windows <名前か JSON>` と `--window-age <秒>` で渡す。省略すれば今までと同じ出力になる
- 組み込みの見本は、1 枚、重なった 2 枚、手前の小さなパネル、全画面、ウィンドウの無いデスクトップ。背景の画像も同じ矩形から作り、見た目と判定をそろえる
- ギャラリーにウィンドウの年齢(0 分・10 分・1 時間・2 時間)を足す。今のギャラリーはフレームを作ったあとで `displays` を入れているので、順を入れ替える(A2)

## 4. 隠れと描き方

- 配置が変わったとき(`layoutRevision` が増えたとき)だけ、CPU で帯を組み直す。ウィンドウの上辺(上の角を含み、側辺に短く回り込む)と画面の下の隅を根元にし、それより手前の矩形で根元の区間を切る。隠れた根元からは葉先も出さない
- 残った根元から、外へ 20 pt、内へ 8 pt の四角を作り、その四角と交わる手前の矩形だけを添えて GPU に送る。シェーダーはその数枚と角の丸い矩形で判定し、縁をぼかす。全画面のパスと、画素ごとに全ウィンドウを調べることはしない
- 帯より後ろのウィンドウは判定に使わない。外へ出た葉先がデスクトップの上でも後ろのウィンドウの上でも、同じように描ける。描く順は後ろから手前
- 角の丸みは取れない。半径を仮に 16 pt とし、区切り H で試験用のエフェクトの線を実際のウィンドウに重ねて見る。ウィンドウごとに半径がはっきり違えば、上の角を厚くする案(5.1)と食い違うので、角の扱いを作者に決めてもらう。同じときに、内へ 8 pt の帯が左上のボタンに掛からないかも見る

## 5. 苔の作り方(SPEC 4.3)

### 5.0 見た目の方向(区切り J0 で決める)

苔は光や雨と違って生き物なので、どこまで本物に寄せるかを先に決める(2026-11-20、作者の指摘)。比べるのは次の 3 つ。

- 写真に近い苔: 葉の重なりの厚みと、濡れた緑の深さが出せる。帯が細いので、土色や細かい毛まで描くと、白い書類の際で汚れやカビに見えやすい。葉を大きく描くと縮尺が合わなくなる
- 少しだけ理想化した自然の苔(Claude と Codex が推す案): 種類と育ち方は本物に沿い、房の大きさと間隔をほどよく整え、色を澄んだ緑に寄せる。光の当たる側と根元の影で形を見せる。木漏れ日と雨と同じ「現象」の描き方になる
- 光る、幻想的な苔: 作者が参考に示したゲームの画面にある性質を借りる。暗く彩度の低い青緑の地、光る粒のまわりの柔らかいにじみ、奥行きでぼける漂う光の粒。暗い画面で汚れに見えない。一方、作業中の黒い画面では淡い光でも視界の端に残り、漂う粒は動きなので目を引き、点滅の規則(1 秒に 3 回まで)にも気をつける。特定の作品の見た目を写すのではなく、性質だけを借りる

理想化した苔には、ヒカリゴケの光り方を足せる。ヒカリゴケは自分では光らず、レンズ状の細胞が入ってきた光を返してエメラルド色に見える。夜やダークの外観で、暗い所の苔の一部が画面の光を受けてかすかに光る形なら、幻想的に見えても現象のまま描ける。

どの方向でも、生き物らしさは動きではなく時間差で出す。前に見た房が、次に手を止めたとき同じ角で少し育っている。

### 5.1 成長と形

- `MossEffect`、`layer: .surface`、`capabilities: [.windows]`
- 成長の度合いは `g = smoothstep(600, 7200, 年齢 × 生える速さ)`。10 分で生え始め、2 時間で育ちきる
- 場所ごとの「生える順番」の値 T を、縁からの距離と、ウィンドウの ID を種にしたノイズから作り、T < g の所に生やす。小さな群落ごとに芽吹く順番と広がる半径を持たせ、育ちきっても地肌の見えるすき間を残す。上辺の中ほどは途切れがちにし、上の角に厚い塊を寄せる。左右の角は別の種にして、鏡に映したような形を避ける
- 模様はウィンドウの左上からの pt に固定する。凪のたびに変わる値(`showing`)は種に入れない。同じウィンドウには同じ苔が生える
- どの年齢の絵も、その時点の値から直接求める。過去のフレームを積み上げないので、ギャラリーで時刻を動かしても同じ絵になる

### 5.2 粒立ちと色

- 群落のなだらかな盛り上がりに、1.5〜2 pt ほどの葉の房の小さな盛り上がりを重ねて高さ場にし、勾配から法線を求める。空からの柔らかい光を土台に、共有環境の太陽の向きによる弱い陰と、根元の陰りを重ねる
- 色は、深い緑、黄緑、くすんだ褐色を、群落と房の単位で混ぜる。根元は暗く、先端は光を透かして明るい。古い中心ほど褐色に寄せる
- 拡大して白い砂のように見えたら、粒を増やす前に、葉先の向き、重なり、根元との明暗の差を直す。実寸で文字より先に緑の線が目に入るなら、帯のつながりを減らす
- 陰、葉先、露、ぼかしも、外 20 pt・内 8 pt の中に収める

### 5.3 深まりと退場

- 浅い: そのウィンドウがすでに育てた苔が、入場のエンベロープで現れる。凪に入ったばかりでも、古いウィンドウの苔を更地に戻さない
- 深い: 仮に `smoothstep(30, 120, depth)` で、育った塊から細い柄と小さな蒴(胞子体)が立つ。位置は種で固定し、長さと数を連続的に変える。共有の風でわずかに揺らす(視差効果を減らす設定では止める)
- 朝露: 太陽が東の低い所(高度 0〜20°)にあるあいだ、葉先のいくつかに小さな光る粒を置く。位置は種で固定し、ゆっくり瞬かせる(点滅は 1 秒に 3 回まで、D19)。夕方の低い太陽では出さない
- 退場: 形を保ったまま、色を明るさの近い鈍い灰緑へ寄せて抜く。最後の透明度はコアのエンベロープに任せる

### 5.4 雨で濡れる(SPEC 9 の未決を閉じる)

- 共有環境に `precipitation`(0〜1、既定 0)を足す。雲量で代わりにすると、雨の無い曇りでも濡れ、`--sky clear` で雨が降っていても乾く
- `Effect` に、自分のパラメータと深まりから降水への寄与を返す静的なメソッドを足す(`note` と同じ形。既定は 0)。雨は今ある `Drops.coverage(depth:intensity:) / Drops.maximumCoverage` を返す。コアは動いているエフェクトの最大を取るだけで、雨の名前も降り方の曲線も知らない
- 苔は数十秒かけて色を深くし、先端の照り返しを少し締める
- 雨を切ったとき、ランダムで選ばれなかったとき、許可を失って止まったときは 0 になる
- この変更は NagiKit と雨に入るので、A2 で固める前に済ませ、雨の基準画像が変わらないことを確かめる

### 5.5 パラメータと負荷

- パラメータ: 生える速さ(0.5・1・2 倍)、広がりの上限(外 20・内 8 pt をまとめて縮める)、色調(自然・黄緑寄り・深緑寄り)
- 毎フレーム描くのは帯の四角の中だけにする。重ければ、帯ごとに「生える順番・高さ・色」をテクスチャに焼いておき、毎フレームは g との比べと光の計算だけにする。焼くかどうかは A2 と B の数字で決める
- 目標: 苔を足しても 95 % 点の増え方は 1.0 ms 以内、3 つを重ねて 16.7 ms 以下、落ちたフレーム 0。ふつうの枚数と、30 枚が重なった配置の両方で測る。活動中は描画も取り込みも 0 のまま、取得だけでアプリの CPU が 0.3 ポイントを超えないこと

## 6. 試験

- 偽の時計と偽の取得元で、3.3 の規則を試す(初見、599・600・7200 秒、移動と大きさの変更、1 pt の累積、前後の入れ替え、消えて番号の再利用、スリープとロックをまたいで続くこと、起動し直しで 0)
- 遅れて届いた取得、取得中のディスプレイの抜き差しと Space の切り替えで、古い配置が戻らないこと
- 負の座標、異なる倍率、ディスプレイをまたぐウィンドウで、pt と画素の対応が合うこと
- `nagi-render` とギャラリーが、同じ見本の配置で同じ画素に線を出すこと
- 隠れの基準画像には、「根元だけ隠れる」「葉先だけ隠れる」「後ろのウィンドウに張り出す」「デスクトップに張り出す」の 4 か所を入れる

## 7. 作者に決めてもらうこと

決めたこと(2026-11-20、作者は 7 章の案をすべて採った。DECISIONS D32):

- Mac のスリープ中も苔は育つ(`ContinuousClock`)
- 苔の既定はオン。エフェクトの一覧を保存している人は、そのまま(苔はオフで、メニューから足す)
- 共有環境に降水を足す(5.4)
- 活動中は 30 秒おきにウィンドウの一覧を取る。原則 6 の例外として認める(描画も取り込みもしない)

これから決めること:

- 区切り H で: 角の丸みと上の角の厚さ、全画面のアプリに苔を出さないこと
- 区切り I で: 凪の間の取得の頻度

## 8. 2 つの案の突き合わせ

骨組みは両案で同じだった。コアを先に作って固め、苔はパッケージとして足す。年齢はウィンドウの矩形が変わらずにいた時間で、前後の順の変化は数えない。苔の形はウィンドウの ID を種にし、深まりは胞子体と露に使う。

| 採った点 | 案 | 理由 |
|---|---|---|
| `WindowSnapshot` に `layoutRevision` と役割(`.occluder`)を持たせる | Codex | 形を作り直す時を知るため。メニューやパネルの下に苔を出さないため(Claude の案は層 0 以外を捨て、メニューの上に苔を描いていた) |
| 層 1 以上でもディスプレイ全体を覆うものは除く | アドバイザー、1.2 の測定 | Dock と見られる全画面のウィンドウが、すべての苔を隠す |
| 下の隅は Dock の外(`usableAreas`)に置く | Claude | 層 20 の矩形からは Dock の形が分からない |
| ロック、スリープ、Space の切り替えで記録を捨てない。`.optionAll` で追う | Claude、アドバイザー、1.2 の測定(Codex の案は捨てる) | 捨てると 2 時間がめったに貯まらない |
| 壁時計をやめて `ContinuousClock` か `SuspendingClock` | アドバイザー(Claude の案は壁時計) | 時計を合わせても年齢が跳ばない |
| 年齢を早める試験用の起動オプションを固める前に入れる | アドバイザー | 起動し直すと 0 に戻るので、実画面の確かめができない |
| 降水はエフェクトの静的なメソッドで申告し、雨は今の被覆の曲線を返す | Codex(Claude の案はコアが天気のヒントから入れる) | コアが雨の降り方を真似なくて済む |
| 活動中は 30 秒おき | アドバイザー(Claude 5 秒、Codex 5 秒) | 間隔で変わるのは時刻の精度だけ |
| 凪の間の頻度は 2・5・15 Hz を測って決める | アドバイザー(Claude 2 Hz、Codex 15 Hz) | 15 Hz は雨と重ねると CPU が重い |
| 帯は配置が変わったときに CPU で組み、隠れた根元を切る | Codex、アドバイザー(Claude の案は画素ごとに全ウィンドウを調べる) | GPU の余裕が 1.8 ms しかない |
| 角の丸みは区切り H で見る | アドバイザー(Codex は J) | 角を厚くする案と食い違うかが早く分かる |
| ギャラリーの順序の直しを固める前に入れる | Codex | 見本のウィンドウの所属を決めるのに `displays` が先に要る |
| 所属するディスプレイは持たない | アドバイザー(Codex は持つ) | `frame` と `displays` から求まる |
| 苔の既定がオンになる経路を前提に書く | Codex | 今の `defaultEnabled` は登録だけで苔をオンにする(コードで確かめた) |
