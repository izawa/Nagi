# M2 の記録

M2-PLAN の段階ごとに、作ったもの、確かめたこと、決めたことを書く。

## 段階 A 取り込みと選び方(2026-11-20)

計画(M2-PLAN 4 章)のとおり、コアを先に仕上げた。取り込みのサービスの下地は Codex が書き、Claude がエンジンにつないだ。

- 取り込み(`BackdropCapture`): ディスプレイごとに `SCStream` を 1 本、自分のアプリを除いて、凪が出ているあいだだけ動かす。退場では最後の 1 枚を保ち、隠れたら捨てる。大きさは凪の描画先と同じ画素数にし、頻度は描く速さに合わせる。開始に番号を付け、止めたあとに遅れて届いたフレームを無視する。ディスプレイの配置が変わったときだけ作り直す
- 選び方(`EffectSelection`): 選択モードとランダムモード(選んでから 30 分は同じもの)を 1 つの経路にした。凪が出るときに決め、出ているあいだは変えない。許可のないエフェクトは選ばない。天気のヒントは動いているエフェクトから求める
- 許可を失ったら、その凪から取り込みのエフェクトを外す。空になれば引く。取り込みが止まったとき(利用者の停止、許可なし、失敗)も同じ。許可のないことしか理由がないときは、5 秒おきに確かめ直す
- `FrameState` に、デスクトップのディスプレイの配置と、凪が出た回数を足した(雨の粒をデスクトップ全体に配り、出直したら始め直すため)
- 設定の移行: 一覧の無い設定は「許可の要らないエフェクトだけオン」と読む。雨を足しても勝手にオンにならない(試験を足した)。メニューに「1 つを選んで出す」、設定の一般に「エフェクトの出し方」を足した
- 許可の案内: 設定に「権限」タブを足した(状態、許可を求める、システム設定を開く、使い方の説明)。許可を求めた直後は「返事を待っています」とし、アプリが前に出たときに確かめ直す。許可の要るエフェクトは名前に「画面収録の許可が必要」と添え、オンにすると権限のタブを開く。メニューに理由の 1 行を出す(設定に並ぶエフェクトだけ)
- 試験用のレンズ(`--debug-lens`、`nagi-render lens`): 取り込んだ画面を拡大して見せる丸いレンズが 6 つ、ゆっくり動く

### Codex のレビュー(段階 A)

2 回で 18 件の指摘をすべて直した。主なもの: 凪が出る瞬間に選び方の変更がエンジンの設定の変更として扱われて再入し、落ちる(いちばん重い)、許可を失ったときや取り込みが止まったときにエフェクトを外して引く、ランダムで選んだものが許可を失っても次の凪が出なくならない、許可を求めた直後を返事待ちにする、取り込みの頻度を描く速さに合わせる、凪が隠れているあいだのメニューの 1 行を次に動くエフェクトから求める、`nagi-render --debug-alpha` でも背景を渡す。

### 負荷(5K・60 Hz、凪が出て 61 秒後から 15 秒、正午、快晴)

| 設定 | GPU の利用率 | 凪の CPU | 1 フレームの GPU の時間(5 秒ごとの平均 / 95 % 点 / 最大) | 落ちたフレーム |
|---|---|---|---|---|
| 木漏れ日だけ | 86 % | 11.0 % | 9.0〜14.2 / 15.3 / 16.1 ms | 起動直後の 1 回だけ |
| 木漏れ日、取り込み、レンズ | 89 % | 11.9 % | 13.6〜14.1 / 15.2 / 17.7 ms | 起動直後の 1 回だけ |
| 同じものを 30 fps で | 66 % | 6.7 % | 15.0〜15.4 / 16.4 / 19.9 ms | 0 |

- 取り込みと背景の合成を足しても、凪の 1 フレームの GPU の時間はほとんど変わらず、利用率が 3 ポイント上がっただけだった。M0 の S4 の「20〜30 ポイント増」は、画面が動き続ける条件の値だった。凪の間の画面はほぼ静止しているので、取り込みの仕事は小さいと見ている
- 木漏れ日だけで 95 % 点が 15.2 ms 前後あり、雨に残る余裕は 1.5 ms ほど。雨は粒のあるところだけを塗る描き方が要りそう(段階 B で決める)
- 30 fps では 1 フレームの時間がかえって長い。GPU の負荷が下がると GPU が速度を落とすためと見ている

### 区切り E 取り込みと許可(作者)

- 設定の権限のタブから許可を求めた。macOS のダイアログで許可すると「終了して再度開く」が出た。開き直して最初に取り込むとき、「システムプライベートウインドウピッカーをバイパスして画面とオーディオに直接アクセス」の確認が出た(M0 と同じ)。許可した
- レンズに後ろの画面が映った。レンズの中にレンズ自身や二重の木漏れ日は映り込まず(自分のアプリを除いた取り込みが効いている)、メニューバーに紫のインジケータが出た。取り込みは凪が出てから 0.11〜0.16 秒で最初のフレームが届いた
- 紫のインジケータから共有を止めると、レンズだけが消え、木漏れ日は続いた(記録: `userStopped`)
- システム設定で許可を外し「あとで行う」を選んだ。次の凪では、許可の確認がまだ「あり」を返したのでレンズを選んだが、取り込みの開始で許可なし(`notPermitted`)になり、33 ms でレンズを外して木漏れ日だけで続けた
- 途中で「木漏れ日も出ない」場面があった。Nagi の設定ウインドウがシステム設定の後ろに開いたままで、設定を開いているあいだは凪を止める決まり(D26)が効いていた。不具合ではない
- 確かめていないこと: 画面共有の 2 つの設定でのレンズ、取り込みの遅れ(凪の間は画面がほぼ動かないので、雨で見る)、2 台のディスプレイ、許可の初期化(`tccutil reset`)からの流れ
