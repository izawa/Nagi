# M4 水中の光の計画

版: 0.1(2026-11-21)/状態: 作者が計画を承認(2026-11-21)。段階 A の前

M4 では、4 つ目のエフェクト「水中の光」(`caustics`)を作り、v0.4 にする。画面を澄んだ浅い水の底に見立て、波立つ水面で屈折した日の光が底に作る明るい網目を描く。光と屈折で見せる表現から作っていく、という作者の方針(2026-11-20)の最初の 1 つである。完了の条件は 2 つある。作者が実際の画面で見た目を通すことと、コアに手を入れずに足せたこと(M2・M3 と同じ)。

計画は Claude と Codex がそれぞれ独立に作り、突き合わせて 1 つにした。アドバイザーにも相談した。どちらの案から何を採ったかは 8 章に書く。

## 1. 前提

- 使えるものは揃っている: 太陽と月(位置、色温度、月齢)、雲(`sunOcclusion`)、風(平均の風と突風の前線)、降水、深まり、ディスプレイの実寸と EDR の余裕。NagiCore と NagiKit は変えない見込み
- 同じ光の層(`.light`)に木漏れ日がある。出力の考え方(ライトは影、ダークは光、EDR)、雲で模様だけが溶けること(D20)、月明かり(D21・D27)は木漏れ日にならう
- 点滅の余裕がない。苔・木漏れ日・雨を `desk-light.png` の上で重ねた場面は、1 画素の 1 秒の最多がすでに 3 回(上限)で、3 回の画素が 13 ある(M3-LOG)
- GPU の余裕も小さい。苔・木漏れ日・雨の本降りで、1 フレームの 95 % 点が 14.3 ms 前後(5K・60 Hz。上限 16.7 ms)

## 2. 見立てと物理

- 画面を真上から見た水平な底とする(上が北、右が東。木漏れ日と同じ)。水深 D は 18・28・40 cm を見比べて作者が決める(既定の案 28 cm)
- 水面の高さ h(x, y) の法線で、太陽の光を空気から水へ屈折させ(屈折率 1.333)、深さ D 進んだ底の着点を求める。光が寄った所が明るい弧になり、着点の順が入れ替わる折り返しで、枝分かれと明るい交点ができる
- 太陽は円盤なので、網目はぼける。直径はおよそ D × 0.0093 / 1.333(水の中で角度が縮む)。28 cm で約 2 mm。太陽が低いと楕円にのびる。これが網目の細さの物理の下限で、点滅を抑える助けにもなる
- 水は光を失わないので、底の明るさの平均は平らな水面と同じ(1)。網目は 1 より明るく、そのあいだは 1 より暗い

## 3. 画面での見え方

| 場面 | 描き方 |
|---|---|
| ライト | 網目のあいだに、ごく薄い青緑を含む影を置く。網目の芯は影が抜け、紙の白が浮かぶ。最大の影の濃さを 0.10 と 0.14 で見比べる |
| ダーク | 光の集まる所だけに、日の光の色を α 付きで置く。網目のあいだは元の暗さのまま |
| EDR | 芯と交点だけを白より明るくする案。点滅の検査は PNG で白を超える分を切ってしまうので、浮動小数で数える道を作れたときに限る。作れなければ SDR で出す |
| 月夜 | 同じ水面を月の方向から照らす。ライトは涼しい薄影、ダークは銀青の筋。既定はオン(木漏れ日と同じ) |

- 明るさは、平らな水面を 1 とした照度に露出の曲線 `1 − e^(−k E)` を掛けて決める(交点に階調を残す。木漏れ日の D18 と同じ考え)
- 雲が太陽を隠すと、網目だけが溶けて、画面全体の明るさは変わらない(D20)。照度を露出の前に 1 へ寄せる形をまず試し、平均が動いて見えたときだけ、木漏れ日と同じ平均を求める処理を足す
- 屈折させるのは仮想の日の光だけで、画面の中身は動かさない。画面収録の許可は要らない

## 4. 水面の動き

- 進む向きと波長の違う波をいくつか重ねる。5 本(主な波 2、斜めの波 2、ゆるいうねり 1。Codex の案)と 12〜16 本(Claude の案)を、波の傾きの大きさをそろえて段階 A で見比べる。5 本では干渉の格子に見えるおそれがある
- **速さは物理ではなく点滅の規則から決める。** 水の波の本当の速さ(ω = √(g k))だと、波長 8 cm で 1 秒に約 4.4 回、24 cm でも約 2.5 回、1 本の波だけで光の線が 1 画素を横切る。周期を 5〜11 秒(短い波は 3〜7 秒)に落とし、水がゆっくり動いて見える。D19 で突風の前線を遅くしたのと同じ、意図した物理からのずれとして記録する
- 周期は整数比にそろえず、種から決める。繰り返しに気づかないことと、途中の時刻へ飛んでも同じ絵になることを両立する。時計は共有の `wind.time`(視差効果を減らす設定では遅くなる)
- 平均の風: 風下へ進む波ほど育つ。風向きが変わっても、網目全体がその場で回って見えない
- 突風: 共有の突風の前線(秒速 25 cm)が来た所から、弧の間隔が端から順に詰まる。明るい帯を走らせない
- 深まり: 浅いうちは幅の広い波だけの柔らかい弧。20〜40 秒で斜めの波が育って網目が閉じ、30〜50 秒で細かい波と突風への応答が加わる。50 秒より先は上限を置く
- 入場と退場: 動いている水に直射が戻るように網目のコントラストが上がり、退場ではコントラストが先に抜ける。水深は凪のあいだ変えない
- 雨: M4 では雨の輪を水面に足さない。点滅が足りなくなったときの手として、降水が増えるほど細かい波とコントラストを控える(コアの変更は要らない)

## 5. 描き方と負荷

- **Codex の「光の束を配る」方式を既定にする。** 水面の固定の格子(実寸で約 1 mm)の各点で屈折させ、底の着点のまわりに、太陽の円盤の楕円の重みで光の量を低解像度のテクスチャ(5K の 1/4、1280 × 720、`r16Float`)へ足し込む。太陽のぼけはこの段で入る。最後に一度だけ、実解像度へ拡大して出力に重ねる
- 水面をゆがめた三角形を描く方式(Claude の案)は採らない見込み。細い三角形がテクセルをまたぐたびに光の総量が揺れ、それ自体が点滅のもとになりうる(アドバイザーの指摘)
- 段階 A の単体試験で次を確かめて決める: (a) 光の点がテクセルの境をまたいでも、テクスチャ全体の光の量がフレームごとに変わらない、(b) 平らな水面は一様に塗れる、(c) 大きくぼけた所に光の点の粒が見えない(見えたら、その所の広がりに合わせて配る幅を広げる)
- 一番細い網目の芯が、作業用のテクスチャで 2〜3 テクセル以上あること(最も浅い水深で)
- 目標: 水を足した差が 1 フレームの 95 % 点で 0.7 ms 以内、4 つを重ねて 15.2 ms 以内。超えたら、配る範囲、格子の細かさ、テクスチャの解像度の順に下げる

## 6. 点滅

- 判定は、任意の 1 画素・任意の連続 1 秒で 3 回まで(`Tools/flicker.py --step 1`)。水だけでは 2 回以下を調整の目安にする
- **見た目を見ていただく前に、段階 A で動かして数える。** 水深の候補ごとに、最大の風の連番を作って検査し、通ったものだけを静止画で見ていただく。あわせて、ライトの影 0.10〜0.14 で、網目の線が 1 本白い所を通るだけで 1 回と数えられるかも確かめる
- **重ねた場面は段階 B で検査する**(リリースの前ではなく)。水・木漏れ日・雨を `desk-light.png` の上で。通らなければ、降水で水を静める手、それでも駄目なら木漏れ日か雨と同時に出さない(選び方の決まりを変えるので作者が決める)
- 検査する場面: 夏至の正午の快晴と最大の風、D19 の突風の時刻(種 1 と 7)、冬至と夕方の低い太陽、雲の通過、満月、深まりの 20〜50 秒、入場の途中の入力。ライトとダーク

## 7. 段階と作者の区切り

| 段階 | 作るもの | 作者が見ること |
|---|---|---|
| A 静止した浅瀬 | パッケージと登録、光の束の描画と単体試験、波の本数の比較、水深 3 案の点滅の検査 | 区切り W1(約 15 分): 点滅を通った水深の静止画(白い本文と暗い本文、実寸と拡大)から、底の深さと網目の見え方を選ぶ |
| B 風が渡る | 波の動き、平均の風と突風、深まり、入退場、重ねた場面の点滅の検査 | 区切り W2(約 15 分): 弱い風・既定・突風を実画面で。止まって見えない最小の動き、本文から目をそらさない速さ。木漏れ日と並べる |
| C 空と夜 | 雲、低い太陽、月、EDR(浮動小数の点滅の検査ができれば)、パラメータ | 区切り W3(約 15 分): 雲の下の残り方、月明かりの既定、EDR の上限 |
| D 重ねて読む | 普段の画面で水だけ、木漏れ日と水、4 つすべて。自然な空で 10 分 | 区切り W4: 「浅い水の底で読んでいる」と感じるか |
| E リリース候補 | v0.4 の DMG、負荷の測定、点滅の一覧 | — |

各段階の終わりで Codex にコードのレビューを頼む。

- 同じ光の層の 2 つの並び: 今の `FrameRenderer` は層だけで並べ替えていて、同じ層どうしの順を決めていない。段階 A で、アプリと `nagi-render` で木漏れ日と水の順がそろうかを確かめる。決まりが要るなら、それはコアの小さな変更になるので作者に伝える
- パラメータ: 設定に出すのは強さと月明かり(案)。水深、波、露出はギャラリーで作者が調整する

## 8. 作者に決めてもらうこと

- 水がゆっくり動くこと(点滅の規則のため、本物の水の波より遅い)
- 水深(区切り W1)
- 木漏れ日と同時に出すか(案: 出す。木陰の浅瀬として読めるかを W2 と W4 で見る)
- 重ねた場面で点滅が通らないとき、同時に出さない決まりを作るか
- EDR を使うか(浮動小数の点滅の検査ができてから)

## 9. 2 つの案の突き合わせ

骨組みは両案で同じだった。屈折を 1 回だけ計算し、低い解像度で底の明るさを求め、木漏れ日と同じ出力(ライトは影、ダークは光)にする。雲は D20 にならい、雨の輪は足さず、コアは変えない。

| 採った点 | 案 | 理由 |
|---|---|---|
| 光の束を楕円の重みで配る描き方 | Codex | 細い三角形がテクセルをまたぐ揺れ(点滅のもと)が起きにくい。単体試験で確かめて決める |
| 太陽のぼけを 1.333 で割る | Codex | 水の中で角度が縮む。Claude の案は割っていなかった |
| 波の速さを点滅の規則から決める | アドバイザー(Codex の遅い周期を採る) | 物理の速さでは 1 本の波で上限を超える |
| 静止画の前に動かして点滅を数える | アドバイザー | M2 の雨は見た目を決めてから点滅を直すのに何度もかかった |
| 重ねた場面の点滅を段階 B で検査する | アドバイザー | 3 つを重ねた場面はすでに上限ちょうど |
| 波の本数を見比べて決める | アドバイザー(Codex 5 本、Claude 数十本) | 5 本は格子に見えるおそれ |
| 雲はまず照度を 1 へ寄せる | アドバイザー(Codex は平均を求める処理) | 平均は物理的に 1 なので、処理を足さずに済むかもしれない |
| EDR は浮動小数の検査ができてから | アドバイザー、Codex | PNG の検査は白を超える分を数えない |
| 水深 3 案(18・28・40 cm) | Codex(Claude は 30〜60 cm) | 網目の大きさを実寸で選べる |
| 段階を 5 つ(A〜E) | Codex(Claude は 3 つ) | 見た目、動き、空、重ね、リリースで作者が見るものが違う |
| 雨で水を静める手 | アドバイザー | 重ねた点滅の余裕を、コアを変えずに作れる |
