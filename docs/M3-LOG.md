# M3 の記録

## 段階 A1 ウィンドウ情報(2026-11-20)

計画は M3-PLAN、決めたことは DECISIONS D32。

### 作ったもの

- NagiKit: `FrameState.windows`(`WindowSnapshot`: 手前から順の `WindowInfo`、`layoutRevision`、`usableAreas`、`desktopSeconds`)。`.windows` を宣言しないエフェクトには `nil` を渡す(`FrameRenderer`)
- NagiCore の `WindowTracker`: 年齢と役割の規則(M3-PLAN 3.2、3.3)。試験のため、時計と一覧を外から渡す純粋な型にした
- NagiCore の `WindowService`: 一覧を専用のキューで読み、最新のスナップショットを 1 つだけ持つ。読み方は 2 種類ある
  - `.visible`(`.optionOnScreenOnly`)は、画面に出ているウィンドウを手前から順に読む。凪の間に使い、スナップショットを作る
  - `.all`(`.optionAll`)は、画面の外のウィンドウも含めて読む。凪でない間に 30 秒おきに使い、年齢だけを更新して、消えたウィンドウを忘れる
- エンジン: 凪に入るたびに、新しい `.visible` の読み取りが届くまでウィンドウを渡さない。凪の間は 1 秒に 5 回読む(A2 で 2・5・15 Hz を測って決める)。ディスプレイの配置が変わったとき(EDR の余裕だけの通知は除く)と、Space が切り替わったときは、それまでのスナップショットを捨てる。凪でない間は、ウィンドウを使うエフェクトがオンで、一時停止・抑止・ロック・動画の抑止のどれでもないときだけ、30 秒おきに `.all` を読む
- 試験用のエフェクト `windowcheck`(DebugEffects): ウィンドウの枠(角の丸み 16 pt を仮定。緑は苔が生える、赤は覆うだけ)、上辺の帯(外 20・内 8 pt。年齢が 10 分から 2 時間に進むにつれて左から塗る)、画面の下の隅を描く。手前のウィンドウが覆う所と、根元の辺が覆われた帯は描かない。アプリは `--debug-windows` で登録し、`--debug-window-age-scale <倍>` で年齢を早める
- `nagi-render`: `--windows single|overlap|panel|fullscreen|empty|<JSON>` と `--window-age <秒>`(既定 7200)。見本の配置は `WindowLayout` が持ち、ギャラリーでも使う予定
- 試験: `WindowTrackerTests` 12 件(年齢、1 pt の許容と累積、前後の入れ替え、画面の外、消えた番号の再利用、役割、`layoutRevision`、デスクトップの年齢、年齢の倍率、見本の配置の拡大と検査)

### 実測で分かったこと

`.optionAll` の一覧は、画面に出ているウィンドウだけを取り出しても、前後の順になっていなかった。同じ時刻に読んだ `.optionOnScreenOnly` と並びが違う(M3-PLAN 1.2 の測定)。Apple の説明も、手前から順と書いているのは画面に出ているものの一覧だけである。そこで、スナップショットは `.visible` だけから作る。

## 段階 A2 コアを固める前の仕上げ(2026-11-20)

### 降水の受け渡し(M3-PLAN 5.4、D32)

- NagiKit: `SharedEnvironment.precipitation`(0〜1)と、`Effect.precipitation(_:)`(既定は 0)
- `FrameRenderer.update` が、動いているエフェクトの申告の最大(0〜1 に収め、NaN は 0)を共有環境に入れ、描くのに使うフレームを返す。エンジン、`nagi-render`、ギャラリーは、返ったフレームで描く。動いているエフェクトの組が変わったら、エンジンは取っておいたフレームを捨てる(雨が止まったあと、ほかのディスプレイが古い降水で描かないため)
- 雨は、粒が覆う割合を本降りの割合で割った値を返す。粒と同じ曲線なので、濡れは雨と一緒に来る。2 分で 1、強さ 1.5 でも 1 まで
- 雨と木漏れ日の絵は変わらない。同じ引数の 3 枚の連番を、変更の前後で描いてバイト単位で比べ、すべて同じだった
- 試験: レンダラーに 1 件(最大、上限、NaN、止まったエフェクトは 0)、雨に 1 件

### 凪の間の読み取りの頻度

別のプログラムで、画面に出ているウィンドウの一覧を、`WindowService` と同じ形で 30 秒ずつ読んだ(開発機、ウィンドウ 11 枚)。

| 頻度 | そのプログラムの CPU | 1 回の時間(中央値、95 % 点) | WindowServer の CPU |
|---|---|---|---|
| 読まない | 0 % | — | 32.0 % |
| 2 Hz | 0.2 % | 2.3 ms、10.5 ms | 32.3 % |
| 5 Hz | 0.5 % | 2.4 ms、10.8 ms | 32.3 % |
| 15 Hz | 1.3 % | 2.2 ms、10.5 ms | 32.0 % |

作者は 1 秒に 5 回を選んだ(区切り I、2026-11-20。`NagiEngine.windowReadingsPerSecond` の既定のまま)。凪の間にウィンドウが変わるのは、アプリが自分でウィンドウを開いたときぐらいで、それも 0.2 秒以内に追いつく。

WindowServer の CPU は、どの頻度でも読まないときと差が無かった(このときは作者がほかの作業で画面を使っていて、WindowServer は 32 % 前後だった)。M3-PLAN 3.4 の「15 Hz で 1 コアの 15 %」は見込みすぎだった。1 回にかかる時間の多くは CPU を使っていない。

## 段階 B0 見た目の方向(2026-11-20)

ウィンドウの上辺に沿って小さな房を並べる試作を、3 つの方向(A 写真に近い、B 少し理想化した自然な苔、C 光る苔)で描き、白い書類と黒いエディタの背景の計 6 枚を、作者が実寸で見た(区切り J0)。最初の版は均一な緑の帯で、拡大すると砂粒のノイズに見えたので、房を 1 つずつ置く形に直してから見てもらった。

作者の判断:

- 色は B
- 3 つとも、生え方にもう少し本物らしさがほしい。今は場所ごとにでたらめに凸凹している。本物の苔は、生え始めたところを中心にして、高さは抑えられたまま左右に広がっていく。そこまで凸凹しない
- 苔の種類はいくつかあってよい。作者が写真で示したのは次の 3 つ
  - タマゴケ: 細い葉の房。赤みのある柄の先に、丸い胞子体(蒴)が付くのが特徴
  - ホソバオキナゴケ: こんもりとした丸い姿。テラリウムの定番
  - コツボゴケ: 透き通るような緑の葉。水を含むときらきら光る

### 生え方と種類を描き直す(2026-11-20)

Codex にも、私の案を見せずに生え方と 3 種の描き方を考えてもらった。骨組みは同じで、群落を CPU で並べて渡す私の案より受け渡しが要らないので、シェーダーの中で群落を求める Codex の形を採った。

- 群落: ウィンドウの番号から、上辺のおよそ 96 pt ごとに 3 分の 2 の割合で起点を置き、上の両角には必ず置く(角が最初に芽吹く)。起点から離れた所ほど多くの成長が要り(`到達値 = b + (1 − b)(x / R)²`)、2 時間で片側 35〜65 pt まで広がる。届かない所は 2 時間たっても地肌が見える
- 断面: 低く、頂は縁の少し外。起点に近いほど厚く、成長の先端の 12 pt で肩が丸くなる。隣の群落とは浅いくぼみで分かれる。上の縁は房やドームの小さな起伏だけで不揃いにし、場所ごとのでたらめな凸凹はやめた
- 種類(群落ごとに 1 種): タマゴケ(濃い緑の房、細い針の葉)、ホソバオキナゴケ(淡い緑の丸いドームの連なり)、縦に細かく立つ芝のような苔(最初はコツボゴケのつもりで透ける広い葉を描いたが、穴が空いたように見えると作者が言ったので変えた)
- 胞子体: タマゴケの群落が、その場所に現れてから 1〜1.5 時間で大人になり、そこから 30 分で赤茶色の細い柄と茶色い丸い蒴が増える(作者の案。値は仮)。起点に近い古い所だけ。凪が深まると柄が伸びる(SPEC 4.3 の「深い: 胞子体が立ち上がる」)
- 角: 角の丸みの 85 % あたりで、太さを保ったまま丸い端で止まる。側辺へは垂れない(作者の指摘: 垂れすぎ、細く垂れた部分はウィンドウの飾りの内側に見える)
- 作者は、3 種の違いが実寸で分かること、起点から左右へ育ったように見えることを確かめた

## 段階 C 時間と天気(2026-11-20)

- 退場: 形を保ったまま、色を明るさの同じ鈍い灰緑へ寄せて抜く。退場を始めたときの現れ具合から数えるので、入場の途中で手を動かしても色は跳ばない。最後の透明度はコアのエンベロープ
- 胞子体の揺れ: 共有の風(平均の風と、帯の中ほどの突風)で、背の高いものほど傾く。突風の場所はデスクトップ全体で 1 つの尺度(5K 27 型の 1 pt = 0.233 mm)で求めるので、2 つのディスプレイにまたがるウィンドウでも同じに傾く。「視差効果を減らす」では揺らさない
- 朝露: 太陽が東にあって高さ 0〜20° のあいだ、深い凪で、葉先に小さな粒が付く。位置は種で固定し、約 15 秒の周期でゆっくり明るさが変わる。南中に近づくほど減る(冬の低い太陽で、南中を境に急に消えないため)。雨では減る。明るさは SDR の白まで(苔は広いレンジを求めない)
- 設定: 生える速さ(ゆっくり 0.5 倍・ふつう・速い 2 倍)と広がりの上限(0.6〜1)。SPEC 4.3 の「色調」は足していない。色は区切り J0 で B に決めたので、選べるようにするかは作者と相談する
- 試験: 朝露が東の低い太陽の深い凪だけに出ること、風の傾きが範囲に収まること
