## 1. コンセプト

Nagi は、ウィンドウで埋まった作業中のデスクトップに自然の気配を持ち込む、macOS の常駐アプリ。
手が止まると現れ、手を動かすと引く。風(入力)が止むと海が凪ぐ、が名前の由来。

スクリーンセーバーは長い離席中にしか出ず、壁紙はウィンドウに隠れて見えない。Nagi は自然を「絵」として置かず、作業中の画面そのものに降る光や水としてシミュレートする。森で本を読むとき、目に入るのは木ではなく、ページの上で揺れる木漏れ日である。

### 1.1 設計原則(優先順)

1. **美しさ**【決定】 精緻で美しい表現が最優先。互換性や実装の手軽さより上に置く。
2. **邪魔をしない** 入力中は何も描かない。現れるのは手が止まっている間だけ。
3. **絵ではなく現象** 画像や動画を貼らない。光・水・成長をシミュレートする。知覚できるループを作らない。
4. **静けさは深まる** 止まっている時間が長いほど、表現は深くなる。オン・オフではなく連続量。
5. **コアとエフェクトの疎結合**【決定】 エフェクトは後から足せる。コアはエフェクトの中身を知らない。
6. **作業中の負荷ゼロ** 凪でない間は描画もキャプチャもしない。

原則がぶつかったら番号の小さいほうを優先する。ただし 2 の「入力があったら必ず引く」はコアが強制する安全装置であり、どのエフェクトも破れない(3.3)。

### 1.2 v1 でやらないこと

- キャラクター、通知、実績や育成ノルマなどのゲーム性
- 音
- ネットワーク通信全般(実在の場所の気象データで駆動する「借景」は将来案)
- エフェクトの実行時ロード(プラグイン形式)。エフェクトの追加は、作者がソースにモジュールを足して再ビルドする形に限る【決定】
- Intel Mac と古い macOS への対応

## 2. 体験仕様

### 2.1 凪の状態機械

入力とは、キーボード、マウス・トラックパッドの移動、クリック、スクロールを指す。

```
活動中 ──(無入力が T_onset 続く)──▶ 凪入り ──▶ 凪(深さが増していく)
   ▲                                              │
   └──────────(退場: T_leave 以内)◀──(入力)───────┘
```

| 値 | 既定 | 確度 | 説明 |
|---|---|---|---|
| `T_onset` | 3.0 秒 | 【決定】 | 無入力がこれだけ続くと凪に入る。設定で 1〜60 秒 |
| 入場時間 | 約 4 秒 | 【仮】 | `presence` が 0→1 になる時間 |
| `T_leave` | 0.8 秒 | 【仮】 | 入力から完全に消えるまでの上限。コアが強制する |
| 深さの減衰 | 手を動かしている 1 秒(最後の入力から 1 秒まで)につき 5 秒ぶん。凪が出るまでの待ちでは減らさない | 【仮】 | 下記、DECISIONS D22 |

無入力の秒数は `HIDIdleTime` で読み(3.8)、入力の直後に 0 に戻るので、そのまま `T_onset` と比べる。本物の入力で、最後の入力から凪に入るまでは中央値 2.91 秒だった(M1-LOG)。

コアは 2 つの値をエフェクトに渡す。

- **`presence`**(0〜1): 出現のエンベロープ。入場はゆるやか、退場は速い。瞬時に消すとその変化自体が目を引くので、退場にも短い時間をかける。
- **`depth`**(秒): 凪の深さ。凪の間は実時間で増える。入力があってもゼロには戻さず、活動中に速く減衰させる。マウスに少し触れただけで、育った表現がすべてやり直しになるのを防ぐためである。

エフェクトは `depth` に応じて自分で深まる。浅いうち(目安 20 秒未満【仮】)は、読んでいる文字の判読を妨げる表現をしてはならない。手が止まっていても、資料を読んでいることがあるからである。

### 2.2 凪を抑制する条件

| 条件 | 挙動 | 確度 |
|---|---|---|
| ユーザーが一時停止した | 出さない | 【決定】 |
| 他アプリがディスプレイのスリープ防止を要求している(動画再生、ビデオ会議など。検出は 3.8) | 既定では出さない。設定で変更可。要求が消えてから数秒は出さない | 【仮】 |
| 画面ロック中、スクリーンセーバー中、ディスプレイのスリープ中(検出は 3.8) | 出さない | 【仮】 |
| 低電力モード | 設定に従う(既定: 品質を一段下げて出す) | 【仮】 |
| 「視差効果を減らす」が有効 | 動きを遅く小さくする | 【仮】 |
| 「コントラストを上げる」「透明度を下げる」が有効 | 強さを下げる | 【仮】 |

光過敏への配慮として、点滅的な変化を作らない。どの画素でも、1 秒のあいだの点滅を 3 回以下にする【決定】(2026-11-19、作者の判断。DECISIONS D19)。点滅は、明るさ(相対輝度、SDR の白を 1)が 10% 以上変わって戻る組で、暗い側が 0.8 未満のもの。光過敏への配慮で広く使われている基準と同じ考え方で、小さな面積の例外は設けない。以前の「3 Hz を超える輝度変動を振幅 1% 未満」は、風で揺れる影の縁が掃くだけで超えるので改めた。

波紋だけは、この決まりの例外にする【決定】(2026-11-23、作者の判断。DECISIONS D39)。本物の水の波の速さでは、文字の上で 1 画素が 1 秒に 11〜26 回点滅し、点滅する面積で許す基準(視野 10° の 25 % まで)も、字の密な画面では満たせない。そこで波紋は既定でオフにし、パネル、初回の案内、設定の画面で、スイッチのそばに光過敏の注意を常に出す(オンにする前に読める)。設定の画面の見本も、オンにするまで動かさない。波の影の既定の強さは、無地の所で決まりを守る 0.4 にする。

### 2.3 エフェクトの選択【決定】

- ユーザーはエフェクトを個別にオン・オフできる。複数を同時にオンにできる。
- **選択モード**: オンにしたエフェクトをすべて重ねて出す。重ね順は 3.5 に従う。
- **ランダムモード**: オンにしたエフェクトの中から 1 つを抽選して出す。
  - 抽選は凪入りの時点で行う。凪の最中には切り替えない。
  - 前回の抽選から 30 分以内【仮】なら同じものを使う。短い中断のたびに景色が変わると落ち着かないためである。
- 必要な権限がないエフェクトは選択肢に出すが無効表示にし、理由を添える。権限のダイアログは、ユーザーがそのエフェクトをオンにしたときにだけ出す。
- 画面収録を一度拒否されると、システムのダイアログはもう出ない(5章)。そのあとは、エフェクトをオンにしたときに説明と「システム設定を開く」ボタンを出し、画面収録の一覧へ案内する(2026-11-18 に作者が追加)。

### 2.4 メニューバー

Dock には出さず、メニューバーのアイコンだけで常駐する。アイコンを押すと、メニューではなく小さなパネルが開く(2026-11-20 に作者が決定。メニューの項目は押すとメニューが閉じるので、エフェクトを続けて切り替えられなかった。DECISIONS D34)。中身は次のとおり【仮】。

- エフェクトの一覧(スイッチ。行の右端にそろえる)
- ランダム(切り替え)
- 今すぐ見る(押したあと手が 0.5 秒止まった時点で、晴れの空と深さ 120 秒の深まった凪で 30 秒見せる。30 秒のあとも、最後の入力から凪に入るまでの時間がたっていて、動画や会議で控えていなければ、ふつうの凪として続ける。待たずに見た目を確かめるため。2026-11-18 に作者が決定、2026-11-21 に晴れと深まりを足した。DECISIONS D15、D35、D36)
- 一時停止(1 時間/今日いっぱい/再開するまで)
- 設定…
- Nagi を終了

エフェクトがいま何も描かないか、ほとんど描かないときは、スイッチの下にその理由を出す(木漏れ日なら日の入り後。2026-11-19、DECISIONS D26)。先頭に置くと、切り替えで理由が消えたときにスイッチの位置がずれた(D34)。別の画面へ移る項目(今すぐ見る、設定、終了)は、パネルを閉じてから動く。

### 2.5 設定ウィンドウ

- 一般: ログイン時に起動、現れるまでの秒数、深まる速さ、全体の強さ、動画再生中の扱い、他アプリの画面共有に写すかどうか
- エフェクト: 各エフェクトが宣言したパラメータから自動生成する(3.4)。コアはエフェクト固有の UI を持たない
- 権限: 画面収録の許可状態と、システム設定を開くボタン

初回起動時は小さなウィンドウで、何をするアプリかと、エフェクトの選択を案内する。

## 3. アーキテクチャ

### 3.1 対象環境

| 項目 | 内容 | 確度 |
|---|---|---|
| OS | macOS 27 以降(2026-11-18 に作者が決定) | 【決定】 |
| CPU | Apple silicon のみ(arm64) | 【決定】 |
| 言語 | Swift 6(厳格な並行性チェック)、Metal Shading Language | 【仮】 |
| UI | 設定とメニューは SwiftUI、オーバーレイは AppKit | 【仮】 |
| UI の言語 | 日本語を原文にし、英語を String Catalog で足す | 【決定】 |
| バンドル ID | `org.izawa.Nagi` | 【決定】 |
| 描画 | Metal。下記の方針に従う | 【仮】 |
| 外部ライブラリ | 原則なし。必要なら作者に相談 | 【仮】 |

M0 で動作を確かめたのは macOS 27.2.1 だけである。そこで、最低 OS を 27 にした。

Metal の方針: 従来の Metal API を土台にする。Metal 4(`MTL4…`)や MetalFX、レイトレーシングは、見た目に具体的な利益がある箇所に限って使う。新しさのための採用はしない。エフェクトは GPU をコアの薄い抽象越しに使い、後から移行できるようにしておく。

### 3.2 モジュール構成と依存ルール【決定】

```
Nagi/
├─ App/                    アプリ本体(メニューバー、設定、権限 UI、エフェクト登録)
├─ Packages/
│  ├─ NagiKit/             エフェクト API(プロトコルと値型だけ)
│  ├─ NagiCore/            エンジン(凪の検出、オーバーレイ、合成、各サービス)
│  └─ Effects/
│     ├─ KomorebiEffect/   木漏れ日
│     ├─ RainEffect/       雨
│     └─ MossEffect/       苔
├─ Tools/nagi-render/      オフスクリーン描画ツール(3.12)
├─ Config/                 Local.xcconfig.example など
├─ scripts/                release.sh など
└─ docs/                   SPEC.md、DECISIONS.md、SPIKES.md
```

依存の向きは次のとおり。パッケージ定義で強制する。

- エフェクト → NagiKit のみ
- NagiCore → NagiKit のみ
- App → NagiCore と各エフェクト
- エフェクトは NagiCore も、他のエフェクトも import しない

「後から足せる」とは、作者がソースにモジュールを足して再ビルドすることを指す【決定】。配布済みのアプリにファイルを入れて増やす仕組みは作らない。したがってコード署名の検証を緩める必要はなく、エフェクトは通常の Swift パッケージとして静的に組み込む。

エフェクトを足す手順は「パッケージを 1 つ追加し、App の登録リストに 1 行足す」だけにする。コアにもほかのエフェクトにも手を入れない。

### 3.3 コアの責務

- 凪の検出と、`presence`・`depth` の算出
- オーバーレイウィンドウの生成と破棄(ディスプレイごと)
- 描画ループ、エフェクトの呼び出し、合成、最終出力
- サービスの提供: 共有環境(3.6)、画面キャプチャ(3.9)、ウィンドウ情報(3.10)
- エフェクトの選択とランダム抽選、パラメータの保存
- 安全装置: 最終出力に `presence` のエンベロープを必ず掛ける。エフェクトが何を描いても、入力から `T_leave` 以内に画面から消える
- 品質段階の決定と電力管理(3.11)

### 3.4 エフェクト API(NagiKit)

以下は方向を示す例示。最終形は M1 で確定する【仮】。

```swift
public protocol Effect: AnyObject {
    static var descriptor: EffectDescriptor { get }
    init(context: EffectContext) throws          // デバイス、ピクセル形式、自分のリソース
    func update(_ frame: FrameState)             // 1 フレームに 1 回。シミュレーションを進める
    func render(_ frame: FrameState,             // ディスプレイごとに 1 回
                view: DisplayView,
                encoder: EffectEncoder)
    func releaseResources()                      // 凪でない間に呼ばれうる
    static func note(_ frame: FrameState) -> LocalizedStringResource?  // いま描かない理由。メニューに出す
}

public struct EffectDescriptor {
    public var id: String                        // "komorebi" など。保存キーにも使う
    public var displayName: LocalizedStringResource
    public var summary: LocalizedStringResource
    public var layer: EffectLayer                // .surface < .light < .glass
    public var capabilities: Set<Capability>     // .backdrop / .windows / .extendedRange
    public var parameters: [ParameterSpec]       // スライダー、トグル、選択肢
    public var weatherHint: WeatherHint?         // 例: 雨は曇りを希望する
}
```

`FrameState` が運ぶもの:

| 項目 | 内容 |
|---|---|
| 時刻 | 単調増加の秒、前フレームからの差分、壁時計の日時 |
| 凪 | `presence`、`depth`、局面(入場中/定常/退場中) |
| 環境 | 太陽と月、雲量、風(3.6) |
| 外観 | ライト/ダーク |
| 品質 | 品質段階(3.11) |
| パラメータ | 自分が宣言したパラメータの現在値 |
| 乱数の種 | 同じ種と時刻なら同じ絵になる(検証用) |
| ウィンドウ | `.windows` を要求した場合のみ(3.10) |

`DisplayView` が運ぶもの: ピクセル寸法、スケール、物理寸法(mm)、デスクトップ全体の中での位置、EDR の余裕、`.backdrop` を要求した場合の背景テクスチャ。

契約:

- エフェクトは 1 種類につき 1 インスタンス。シミュレーションはデスクトップ全体の座標で行い、`render` がディスプレイごとに呼ばれる【仮】
- `update` と `render` は描画スレッドから直列に呼ばれる
- 入場と退場の見せ方はエフェクトが決める(雲が晴れる、粒が蒸発する、など)。ただしコアのエンベロープが最終的に強制される
- エフェクトのシェーダーやリソースは、そのエフェクトのパッケージの中に置く。`.metal` はパッケージに `.process` で置き、`device.makeDefaultLibrary(bundle: Bundle.module)` で読む(S9。`swift build` と `xcodebuild` のどちらでも通った)
- 設定 UI は `parameters` から自動生成する。エフェクトは UI のコードを持たない

### 3.5 合成モデル

オーバーレイは、キャプチャしない限り他アプリのピクセルを読めない。ウィンドウサーバが行うのは乗算済みアルファの重ね合わせである。ただし、M0 で測ると、重ねているのは線形の値ではなく、sRGB の符号化した値だった(S2)。

```
enc(画面) = enc(下の画面) × (1 − α) + α × enc(C / α)
```

enc は sRGB の符号化の曲線(1 を超える値にも同じ曲線を延ばす)、C / α は乗算を外した色である。暗くするパッチと色を付けるパッチは、この式と 0.001 以内で合った。乗算を外すと白の 1.5〜3 倍になるパッチも 0.002 以内で合ったが、明るい灰色の上の 3 倍のパッチだけは、式の 1.018 に対して 1.000 で止まった。1 を超える結果がどこで切られたのかは確かめていない。測った条件は、`rgba16Float`・拡張リニアの Display P3 のレイヤー、Studio Display 1 台、ScreenCaptureKit で読んだ値である。

この式では、α 0.08 の黒は符号化した値を 8% 下げ、線形の明るさでは中間の灰色で約 17% 下げる。影の濃さと色の量は、この式を前提に決める。

これでできること、できないこと:

| 操作 | 方法 | 可否 |
|---|---|---|
| 減光(影) | C = 0、α = 減光率 | 可 |
| 色かぶり | α を持ち、C に薄い色 | 可 |
| 加算(光) | α = 0、C > 0 | 不可。α = 0 の色は何も足さない。α 1/1024 では符号化した値で 0.005 ほどしか明るくならなかった(S2) |
| 明るくする | α > 0 で、乗算を外した色を下の画面より明るくする。白より明るくするには EDR の値を使う | 可(S2) |
| 置換 | α = 1 | 可 |
| 屈折、色ごとの乗算 | 下のピクセルが必要 | 背景テクスチャがあれば可 |

各エフェクトは乗算済み RGBA を出力する。作業用の形式はリニアの 16 ビット浮動小数、拡張レンジの Display P3 とする【仮】。最終出力も同じ形式(`rgba16Float`、拡張リニアの Display P3)にする。コアが `layer` の順に重ねる。

| 重ね順 | `layer` | 意味 | 例 |
|---|---|---|---|
| 下 | `.surface` | ウィンドウの表面にあるもの | 苔、落ち葉 |
| 中 | `.light` | その上に降る光 | 木漏れ日 |
| 上 | `.glass` | モニターのガラス面にあるもの | 雨粒 |

この順にすると、苔にも木漏れ日が当たり、雨粒はその全部を屈折させる。エフェクト同士は互いを知らなくてよい。

`.backdrop` を要求したエフェクトには、「キャプチャした画面に、自分より下のエフェクトを合成した結果」をテクスチャで渡す。雨は木漏れ日の存在を知らないまま、木漏れ日ごと屈折させられる。

**階調**: 8% までの淡い影を 8 ビットのアルファで出すと、段数が 20 前後しかなく、なだらかな半影に縞が出るおそれがある。ただ、0〜8% の減光のランプでは、8 ビットのディザなしでも縞は見えなかった(S2、作者の目視)。最終出力は 16 ビット浮動小数にし、ディザは足さない。木漏れ日の半影(朝の広い影、正午の円の縁、ダークの光、満月の月明かり)を白・灰・黒に近い背景で実寸で見て、縞は無かった(DECISIONS D2)。縞が見えるエフェクトが出たら、そのときにディザを足す。

### 3.6 共有環境

太陽、雲、風はコアが 1 つだけ持ち、全エフェクトに同じ値を配る。木漏れ日の葉と、将来の落ち葉が、互いを知らずに同じ風で揺れる。

| 要素 | 内容 | 確度 |
|---|---|---|
| 太陽 | 日時と緯度経度から高度・方位・色温度を求める | 【仮】 |
| 場所 | 既定はタイムゾーンの代表都市。設定で緯度経度を指定可。位置情報サービスは使わない | 【仮】 |
| 月 | 夜は月の位置と月齢 | 【仮】 |
| 雲量 | ゆっくり変動する値(雲の量、0〜0.4)と、いま太陽の直射が雲でどれだけ失われているか(0〜1)。エフェクトの `weatherHint` を混ぜる(雨がオンなら曇りに寄る)。DECISIONS D20 | 【仮】 |
| 風 | 向きと強さ、突風の前線。空間と時間で滑らかに変わるノイズ場。周期を持たない。前線は見えるように 1 秒に 25 cm で渡る(DECISIONS D19) | 【仮】 |
| 降水 | いま絵の中で降っている雨の強さ(0〜1)。動いているエフェクトが自分の降らせる量を申告し(`Effect.precipitation`)、コアがその最大を配る。雨は粒の覆う割合を本降りの割合で割った値を申告し、苔はそれを見て濡れる。エフェクトどうしは互いを知らない(DECISIONS D32) | 【決定】 |

### 3.7 オーバーレイウィンドウ

ディスプレイごとに 1 枚。構成は次のとおり。M0 で確かめた点には S の番号を付けた(ディスプレイ 1 台、Dock は画面の下)。2 台目のディスプレイの抜き差しと配置の変更は確かめておらず、M1 で確かめる。

- 枠なし、不透明でない、背景は透明、影なし。出しても手前のアプリは変わらず、キーウィンドウにもならない(S1)
- `ignoresMouseEvents = true`(クリックを下へ通す)
- ウィンドウレベルは `.popUpMenu`【決定】。開いたままのメニューの上に重なってもよい(作者の判断、2026-11-18)。`.statusBar` では Dock の下に回った。`.popUpMenu` はメニューバーと Dock の上にも出て、その上のクリックは下へ届いた。開いたままのメニュー(Chrome の右クリックのメニュー)の上にも重なった(S1)。スクロール、ドラッグ、ホバーとカーソルは `.statusBar` で確かめたので、M1 で `.popUpMenu` でも確かめる
- `collectionBehavior` は `canJoinAllSpaces`、`fullScreenAuxiliary`、`stationary`、`ignoresCycle`。別の Space、フルスクリーンのアプリ、Mission Control、Stage Manager でも出て、Cmd-Tab と Cmd-` の候補に出ない(S1)
- 中身は `CAMetalLayer`(不透明でない)。EDR 対応ディスプレイでは拡張レンジを有効にする
- 他アプリの画面共有やスクリーンショットに写さない設定を既定にする(`sharingType = .none`)。標準のスクリーンショット(全画面、範囲、ウィンドウ)、ScreenCaptureKit、Zoom の画面全体の共有のどれにも写らなかった(S6)。Apple のドキュメントは `.none` を古い値としているので、macOS を更新したら確かめ直す。写す設定(2.5)では `.readOnly` にする
- ディスプレイ構成の変化に追従する。作り直すのは画面の位置・大きさ・倍率が変わったときだけにする。EDR の余裕が変わるたびにも画面の設定の変更の通知が届くため(S1)
- 出した直後の最初のフレームは表示されないことがある(S1)。入場は 1 フレーム目に頼らない
- オーバーレイを出しても、無入力の秒数は 0 に戻らない(S1)
- 凪でない間はウィンドウを画面から外す

### 3.8 凪の検出

- 最後の入力からの経過秒を、IOHIDSystem の `HIDIdleTime` で取る。権限は要らず、Sandbox の下でも読めた。クリックとキーは数 ms で値が 0 に戻る。M0 で使った `CGEventSource.secondsSinceLastEventType` は、本物の入力を 0.1〜0.4 秒遅れて反映し、入力の直後も 0.5 秒前後までしか下がらなかったので、使わない(M1-LOG 区切り A、DECISIONS D14)
- キー入力のグローバル監視は使わない。入力監視の権限を求めたくないため
- 活動中は、次に `T_onset` に達しうる時刻まで寝る。常時ポーリングしない
- 凪の間は毎フレーム確認する。入力からウィンドウを外すまで、本物の入力で中央値 384 ms・最大 429 ms(退場のフェード 0.4 秒を含む。M1-LOG)
- 動画再生などの検出は、他プロセスの電源アサーションで行う(`IOPMCopyAssertionsByProcess`。S3)。数えるのは他プロセスの `PreventUserIdleDisplaySleep` と `NoDisplaySleepAssertion` だけにする。`Internal…` で始まる種類(powerd が操作のあとに持つ)とシステムのスリープの防止は数えない。Safari(YouTube)は再生の始めと止めから 2〜3 秒以内に前者を持ち、手放した。Zoom は会議を始めて 7 秒後から終えて 1 秒後まで後者を持った。Safari の再生中にも 1 秒ほど消える瞬間が 2 回あったので、消えてから数秒は凪に戻らない(2.2)。QuickTime Player は確かめていない
- 画面のロック、スクリーンセーバー、ディスプレイのスリープは、分散通知の `com.apple.screenIsLocked`・`com.apple.screenIsUnlocked` と、`NSWorkspace` の `screensDidSleepNotification`・`screensDidWakeNotification` で知る(S3)。スクリーンセーバーとディスプレイのスリープでも `screenIsLocked` が届く

### 3.9 画面キャプチャ(背景テクスチャ)

`.backdrop` を要求するエフェクトがオンで、かつ凪の間だけ動かす。

- ScreenCaptureKit を使う。画面収録の許可が必要
- 自分のウィンドウを除外して取り込む。含めると雨粒が雨粒を屈折させてしまう。`SCShareableContent` を画面に出ていないウィンドウも含めて取り(`onScreenWindowsOnly: false`)、自分のアプリを除く `SCContentFilter` を作る。画面に出ているものだけにすると、起動の直後に自分のアプリが一覧に入らず、除外を作れないことがあった(S4)
- フレームは IOSurface のまま `CVMetalTextureCache` で Metal のテクスチャにする(コピーしない。S4)。GPU の処理が終わるまで、フレームごと保持する
- カーソルは取り込まない【仮】
- 凪入りと同時にストリームを開始し、退場で止める。開始を求めてから最初のフレームまで 109〜142 ms だった(S4、一覧の取得と設定の準備を含む)。起動の遅れは `depth` の浅い間に吸収し、雨は最初のフレームが届いてから出す【仮】
- 取り込んだフレームは GPU メモリの外に出さない(5章)
- 負荷: 取り込み中は GPU の利用率が 20〜30 ポイント上がり、取り込む解像度を半分にしてもほとんど下がらなかった(S4、5K・60 Hz)。取り込みを凪の間だけ動かす理由の一つである
- 利用者がメニューバーのインジケータから止めると、`SCStreamDelegate` にエラー −3817 が届く(S4)。その凪の間は取り込みを始め直さない。インジケータを押す操作は入力なので、凪もそこで終わるはずである(M2 で確かめる)
- 取り込み中に許可を取り消し、システムのダイアログで「あとで行う」を選ぶと、動いているストリームは止まらず、知らせも届かなかった(S4)。凪に入るたびに `SCShareableContent` を取り直し、エラー −3801 なら許可のない状態として扱う

遅延について: 画面が変わってから、取り込んだフレームで読めるまで、中央値 20〜35 ms、最大 49 ms だった(S4。60 Hz の Studio Display で、変化を描く側の時間も含む)。凪の間は画面がほぼ静止しているので、この遅れは見えない見込みである。凪を引き金にする設計で、キャプチャの弱点を消せると考えている。雨の上で遅れが見えるかは M2 で確かめる。

### 3.10 ウィンドウ情報

`.windows` を要求したエフェクトに、画面上のウィンドウの一覧を渡す。

- 内容: 手前から順のウィンドウ(番号、矩形、役割、いまの矩形のまま続いている秒数)、配置が変わると増える番号、ディスプレイごとのメニューバーと Dock を除いた範囲。役割は「苔が生える」と「手前を覆うだけ」の 2 つ。小さいウィンドウ、ディスプレイ全体を覆うウィンドウ(全画面のアプリ)、通常より上の層のウィンドウ(メニューバー、開いたメニュー、パネル)は覆うだけ。ただし通常より上の層でディスプレイ全体を覆うもの(Dock の透明なウィンドウ)は除く(M3-PLAN 1.2)
- 取得は `CGWindowListCopyWindowInfo`。macOS 27.2.1 では、画面収録の許可なしで、ウィンドウ番号、矩形、層、前後の順序が取れた。Sandbox の下でも同じだった(S5)。ただし Apple は許可なしで返すキーを文書化しておらず、将来変わりうる。前後の順が保証されるのは画面に出ているものの一覧(`.optionOnScreenOnly`)だけで、全部の一覧(`.optionAll`)は順がそろわなかった(M3-LOG)。そこで、凪の間は画面に出ているものの一覧で重なりを決め、全部の一覧は年齢の記録(最小化や別の Space のウィンドウを含む)にだけ使う
- 「動いた」は、矩形のどれかの辺が 1 pt を超えて変わり、次の読み取りでも同じ新しい矩形だったとき。Space の切り替えでは、一覧がウィンドウを滑っている途中の位置で返すため(M3-LOG 区切り H)。年齢は Mac のスリープ中も進む時計で数え、ロック、スクリーンセーバー、Space の切り替えでは捨てない。Nagi を起動し直すと 0 から(DECISIONS D32)
- 凪の間は 1 秒に 5 回読む(CPU 0.5 %。区切り I で作者が決めた)。凪に入るときは、新しい読み取りが届くまでウィンドウを渡さない。凪でない間は、ウィンドウを使うエフェクトがオンのときだけ 30 秒おきに全部の一覧を読む(作業中の負荷ゼロの例外として作者が認めた。D32)
- 角の丸みは取得できない。半径 16 pt と仮定し、実際のウィンドウに重ねて合うことを作者が確かめた(区切り H)

### 3.11 性能と電力

- 活動中は描画しない、キャプチャしない、ウィンドウを出さない
- 凪の間はディスプレイのリフレッシュレートに同期する(最大 120 Hz)
- 低周波の処理(大きなぼかしなど)は低解像度で行い、鋭さが要る処理(雨粒の縁など)は実解像度で行う
- 品質段階は 2 つ【仮】。標準(M1・M2 世代)と高(M3 世代以降。レイトレーシングなどの参照経路を使える)
- 熱状態と低電力モードを見て、段階を自動で下げる
- 目標: 標準段階で、内蔵ディスプレイの実解像度 60 fps を保つ【仮】

### 3.12 見た目の検証ツール【決定】

エフェクトはウィンドウに依存しない作りなので、画面なしで描画できる。これを使い、実装者(Claude Code)が自分で絵を見て直せるようにする。

- `nagi-render`: エフェクト、時刻、`depth`、背景画像、ウィンドウ配置、外観、乱数の種を指定して、PNG または連番画像を出力するコマンド
- ギャラリー: アプリ内のデバッグ用ウィンドウ。サンプルの背景の上にエフェクトを出し、`depth` や時刻をスライダーで動かせる(DECISIONS D24。メニューバーの「ギャラリー…」。リリース版は `--debug-gallery` で起動したときだけ)
- 基準画像による回帰テスト: 種と時刻を固定した出力を保存し、意図しない変化を検出する

## 4. エフェクト仕様

### 4.1 木漏れ日(`komorebi`)

`layer: .light`/権限: 不要/最初に作る

**物理的な根拠**

木漏れ日が美しいのは、太陽が点ではなく円盤だからである。葉の隙間はピンホールとして働き、地面に太陽の像を結ぶ。

- 太陽の視直径は約 0.53°(約 9.3 ミリラジアン)
- 高さ h、太陽高度 θ の隙間が作る光の円は、光線に垂直な直径が (h / sin θ) × 0.0093
- 地面では太陽の方位に沿って 1 / sin θ 倍に伸び、楕円になる
- したがって、高い梢の隙間は大きく柔らかい円になり、低い枝の葉は形のわかる鋭い影になる

この「高さで変わるぼけ」が再現の核心である。ノイズ模様を揺らすだけの実装にはしない。

**推奨する実装**【仮】

1. 樹冠を 3〜4 層に分ける(M1 では 3 m と 1.5 m の樹冠、0.9 m と 0.25 m の葉。DECISIONS D17、D18)。各層は枝の階層と、葉のインスタンスで構成する
2. 太陽方向の平行投影で、各層の遮蔽を描く。葉は光を少し通すので、色つきの透過率も持つ
3. 各層を、高さに比例した半径の円盤(太陽が低ければ楕円)でぼかす。ガウスぼかしではなく円盤にする
4. 全層の透過率を掛け合わせ、直射光と空の環境光を足す
5. 出力に変換する(下記)

画面の物理寸法を使い、実寸で表現する【仮】。10 m の梢なら光の円は直径 9 cm ほどになる(M1 の 3 m の梢では、太陽が真上で約 2.8 cm)。

将来の参照経路(高品質段階): 太陽を面光源としてレイトレーシングし、蓄積してノイズを除く。

**出力**

| 外観 | 方法 | 既定の強さ |
|---|---|---|
| ライト | 影を落とす。影にはわずかに緑から青の色かぶりを入れる | 最大 20% 減光【決定】(α 0.20 の黒。符号化した値で 20%、線形の明るさでは中間の灰色で約 38%。3.5。区切り B で作者が決めた。DECISIONS D17) |
| ダーク | 暗い面では影が見えないので、光で表す。純粋な加算はできない(3.5)ので、α を持った明るい色で日なたを描く【決定】。白より明るくするには EDR の値を使う | α 0.20【決定】(区切り B で作者が決めた。DECISIONS D17) |
| EDR | 日なたを紙の白より明るくする。対応ディスプレイのみ。α 0.3・白の 2 倍の色のパッチが、隣の白より明るく見えた(S2、作者の目視。取り込んだ値で 1 を超えたかは確かめていない) | 強さは【仮】 |

影(α の黒)は、文字と背景の符号化した値を同じ割合で下げる(3.5 の式から導いた。文字の上では測っていない)。

**動き**

- 幹の揺れ(0.1〜0.3 Hz)、枝の揺れ(0.5〜1 Hz)、葉のはためき(2〜5 Hz、小さく)の 3 階層
- 共有環境の風で駆動する。突風の前線が樹冠を渡っていくのが見えること
- 雲が太陽にかかると、暗くなるのではなく、木漏れ日のコントラストが消えて全体が柔らかくなる

**時刻**

- 太陽の高度で影の伸びと色が変わる。夕方は長く、暖かい色になる
- 夜は月明かりの版にする(ごく弱く、青い)。同じ木を月の位置から照らし、満ち欠けで明るさが変わる。既定はオン、設定でオフにできる【決定】(区切り C で作者が決めた。DECISIONS D21、D25)

**入場と退場**

- 入場: 雲が太陽から離れるように、コントラストが上がってくる。不透明度を上げるだけにしない
- 退場: 雲がかかるように、コントラストが引く

**深まり方**

- 浅い: 高い梢の柔らかい円だけ
- 深い: 低い枝の葉影が加わり、風の表情が増える

**パラメータ**: 強さ、樹冠の密度、葉の揺れ(2026-11-21 に「風の強さ」から改名)、スケール、月明かり

**受け入れ基準**

- [x] 高い隙間は円に、低い葉は葉の形に見える(区切り B)
- [x] 10 分眺めても繰り返しに気づかない(区切り C)
- [x] 突風が渡るのが見える(区切り C)
- [x] 雲で木漏れ日が溶け、また戻る(区切り C)
- [x] 淡い半影に縞(バンディング)がない(2026-11-20)
- [x] 影の下でも本文が普通に読める(区切り B と C)
- [x] 入場と退場が自然現象に見える(区切り C)

### 4.2 雨(`rain`)

`layer: .glass`/権限: 画面収録/`weatherHint`: 曇り寄り

モニターのガラス面に雨粒がつき、後ろの画面を屈折させながら流れ落ちる。背景画像は使わない。雨粒に映るのは作業中の画面そのものである。

背景テクスチャは画面の取り込み(3.9)に頼る。許可のいらない代わりとして `NSGlassEffectView` を試したが、ごく濃いすりガラスにしか見えず、屈折にならなかった(S8)。許可がなければ雨は出さない。

**シミュレーション**【仮】

- 粒は位置、質量、速度、付着状態を持つ。数千個まで
- 新しい粒は、雨の強さに応じてランダムに着く
- 近い粒は合体して育つ
- 質量がしきい値を超えると滑り出す。蛇行し、小さな粒を残しながら落ち、途中の粒を吸って加速する

**描画**【仮】

- 粒を高さ場に描き、滑らかに合体させ、法線を求める
- 法線に沿って背景テクスチャをずらして屈折させる
- レンズのモデルは「近接レンズ」を既定にする。画面はガラスのすぐ後ろにあるので、像は反転せず、拡大されて縁で強く歪む。文字が半ば読めるので、遠景を反転させるモデルより落ち着く
- 質感の要素: 縁の暗い輪、フレネル反射、環境光のハイライト(太陽の向きは共有環境から)、ごくわずかな色分散、粒の下の小さな影と集光
- 雨粒は木漏れ日ごと屈折させる(3.5)。晴れ間の雨では粒が光る
- 流れる粒は、1 コマに実際に進んだ距離に沿ってぶらして描く(動きのぶれ)。像や縁が画素の上を跳ぶと点滅になる(2.2、DECISIONS D31)
- 流れた跡に、細い濡れた膜(航跡)を残す。縁をわずかに暗くするので、無地の上でも見える(D31)

**深まり方**

- 0〜20 秒: 小さな粒がまばらに着くだけ。屈折する面積はごくわずか
- 20 秒〜: 粒が育ち、流れ始める
- 2 分〜: 本降り。粒の総面積は画面の 12% まで【仮】

**雨の暗さ**【決定】: 降り方に応じて、画面全体を少し暗くする。本降りで、符号化した値で 7 % 暗くなる(作者が画面で決めた。設定では 0〜10 %)。暗さは降水と同じく 2 分かけて深まり、退場で消える。雲は画面を暗くしない(4.1)。この暗さは雨そのものの表現で、雨を止めれば暗くならない。雨の層の下にあるもの(画面、木漏れ日、苔)は、どれも同じ割合で暗くなる(DECISIONS D31)。

**退場**: すべての粒が蒸発するように縮んで消える。

**パラメータ**: 雨の強さ、粒の大きさ、屈折の強さ、雨の暗さ

**受け入れ基準**

- [x] 粒の中の像が、後ろの画面と正しく対応して歪む(2026-11-20、区切り E・F・G)
- [x] 流れる粒の軌跡が毎回違い、機械的に見えない(2026-11-20、区切り E・F・G)
- [x] 合体と、残された小粒が見える(2026-11-20、区切り E・F・G)
- [x] 縁がギザつかず、実解像度で鋭い(2026-11-20、区切り E・F・G)
- [x] 浅いうちは、読んでいる文章を邪魔しない(2026-11-20、区切り E・F・G)
- [x] 許可がないときの案内がわかりやすい(2026-11-20、区切り E・F・G)

### 4.3 苔(`moss`)

`layer: .surface`/権限: 不要(ウィンドウ情報を使う)

長く動かしていないウィンドウの上の縁に、苔が生えている。経緯は M3-LOG と MOSS-LOOK-LOG、決めたことは DECISIONS D32・D33・D37。

**成長**

- ウィンドウごとに「いまの矩形のまま続いている時間」を追う(3.10)。10 分で生え始め、2 時間で一度育ちきり、4 時間までさらに育つ
- 苔は群落で育つ。ウィンドウの番号から、上辺のおよそ 96 pt ごとに 3 分の 2 の割合で起点を決め、上の両角には必ず置く(角が最初に芽吹く)。群落は起点から左右へ広がり、2 時間で片側 35〜65 pt、4 時間でその 1.5 倍まで届く。届かない所は地肌が見えたまま残る。隣の群落とは浅いくぼみで分かれる
- 高さは、その場所に苔が届いてからの時間で決まる。届いたばかりの所は薄く、およそ 1 時間半で既定の高さになる。群落は起点から順に背が伸び、4 時間でも左右の端はまだ低い
- 生える場所は、ウィンドウの上辺と上の角。角では丸みの 85 % あたりで、太さを保ったまま丸く終わり、側辺へは垂れない。画面の下の隅には生やさない(Dock の上で宙に浮いて見えた)。メニューバーのすぐ下(14 pt 以内)にあるウィンドウにも生やさない(上半分が隠れて育ちかけに見えた)
- 範囲は縁から外へ 20 pt、内へ 8 pt まで(陰、葉先、胞子体、露を含む)。内容を隠さない
- 形はウィンドウの番号を種にする。同じウィンドウには同じ苔が生える
- 手前のウィンドウに隠れた部分には描かない。根元の辺が隠れた所からは葉先も出さない。重なった 2 枚の苔は、後ろから順に描く

**描画**

- 色は、少し理想化した自然な緑(区切り J0 で作者が選んだ B)。日なたは黄緑、陰はオリーブ(D37)
- 群落ごとに 3 種類のどれか: タマゴケ(細い葉の房)、ホソバオキナゴケ(淡い緑の丸いドームの連なり)、縦に細かく立つ芝のような苔
- 断面は低く、頂は縁の少し外。上の肩は空の光で明るく、窓側の付け根は暗い。太陽と月は共有の空から受け、左右の明暗が時刻で移る。苔全体の明るさは晴れ・雲・夜で変えない
- 葉は細かな起伏に当たる光で見せ、縁の数 pt だけ 1 本ずつ描く。下側はところどころ薄く、窓がのぞく
- 場所ごとに、明るさと色味にむらを付ける。同じ模様を引き伸ばしたり、繰り返したりして見せない
- 木漏れ日がオンなら、苔にも光が当たる(合成の順序で自然にそうなる)
- 雨がオンなら、共有環境の降水(3.6)を見て、濡れて色が深くなる

**深まり方**

- 浅い: 育った分の苔が、入場のエンベロープで現れる
- 大人の群落(タマゴケが、その場所に届いてから 1〜1.5 時間): 赤茶色の柄と茶色い丸い蒴(胞子体)が、まっすぐな上辺に沿って、高さと向きをそろえて立つ。凪が深まると柄が伸び、共有の風でわずかに傾く(「視差効果を減らす」では傾けない)
- 凪の深さ 30〜90 秒で、縁の葉先が光を透かして澄んだ黄緑になる。ダークでは葉先のまわりに淡いにじみが出る
- 朝(太陽が東の低い所、高さ 0〜20°)の深い凪: 葉先に小さな露が付き、約 15 秒の周期でゆっくり明るさが変わる(SDR の白まで)

**退場**: 形を保ったまま、色が明るさの同じ鈍い灰緑へ抜けていく。

**パラメータ**: 生える速さ(ゆっくり・ふつう・速い)、広がりの上限。色調は作らなかった(色は J0 で決め、D37 で日なたを黄緑にした)

**受け入れ基準**

- [x] 拡大しても粒立ちがあり、塗りつぶしに見えない
- [x] ウィンドウごとに形が違う
- [x] ウィンドウの内容を隠さない
- [x] 手前のウィンドウとの重なりが破綻しない

### 4.4 水中の光(`caustics`)

`layer: .light`/権限: 不要

画面を澄んだ浅い水の底に見立て、波立つ水面で屈折した日の光が底に作る明るい網目を描く。同じ光の層では木漏れ日の上に重なり、一緒に出すと木陰の浅瀬になる(区切り W2 で作者が選んだ)。経緯は M4-LOG、決めたことは DECISIONS D35〜D38。

**物理的な根拠**

- 水面の傾きで日の光を空気から水へ屈折させ(屈折率 1.333)、底の着地点を求める。光の寄った所が明るい弧になり、着地点の順が入れ替わる折り返しで、枝分かれと明るい交点ができる
- 太陽は円盤なので、網目はぼける。水の中では角度が縮むので、ぼけの大きさは視直径を屈折率で割り、太陽の高さに応じて斜めにのばす
- 水は光を失わないので、底の明るさの平均は平らな水面と同じ。網目は平均より明るく、あいだは暗い。ただし太陽が低いと、光に背を向けた水面は光を通さないので、平均は下がる

**描き方**

- 水深 28 cm、波 12 本【決定】(区切り W1)。波は種から決まる平面波の和で、波長 4〜24 cm。いちばん長い波は、長さにかかわらずうねりとして必ず残す
- 水面の格子(実寸で約 1 mm 間隔、水に固定)の各点で光を 1 回屈折させ、太陽の像の大きさとその点が受け持つ水面の広がりを合わせた形で、画面の 4 分の 1 の解像度の明るさのテクスチャへ足し込む。最後に一度だけ実解像度へ広げて重ねる
- 描く水面の範囲は、日の高さごとに、最大の傾きで光がどこまで曲がるかから辺ごとに決める。光に背を向けた水面は光を通さない(D38)
- 屈折させるのは仮想の日の光だけで、画面の中身は動かさない

**出力**

| 外観 | 方法 | 既定の強さ |
|---|---|---|
| ライト | 網目のあいだに、ごく薄い青緑を含む影を置く。網目の芯は影が抜ける | 最大 α 0.12 |
| ダーク | 光の集まる所だけに、日の光の色を α 付きで置く | α 0.14 |
| EDR | 使わない(D38)。PNG の点滅の検査が白を超える分を数えられないため | — |

**動き**

- 波の速さは物理ではなく点滅の規則から決めた。本物の水の波よりずっと遅い(周期 5〜11 秒の 4/3 倍。区切り W2 で作者が「ちょっと早い」とした)【決定】
- 流れる速さは、W2 の前の速さの 15〜75 % のあいだで、周期 170・110・70 秒前後の 3 つの揺らぎを足した速さでゆっくり変わる(作者の提案)。速さの時刻の積分を位相の時計にするので、速さが変わっても水は跳ばない
- 波の向きは種で決め、平均の風の風下へ進む波ほど高くする。突風は木漏れ日と同じ共有の前線(秒速 25 cm)で渡り、届いた所から短い波ほど高くなる(最も短い波で 3 倍)。「視差効果を減らす」では半分
- 雲が太陽を隠すと、網目が溶けて画面の平均の明るさへ寄る。暗くはならない(D20、D38)

**時刻**

- 太陽の高さが 10° から 5° に下がるあいだに薄れて消える(木漏れ日と同じ)
- 夜は同じ水面を月の方向から照らす。月明かりは既定でオン、濃さ 0.15(D27 と同じ。D38)

**入場と退場**: 網目は現れ具合だけで出し入れする(木漏れ日の D23 の 2 乗は使わない。2 乗では「今すぐ見る」で 2 秒ほど見えなかった)

**深まり方**

- 凪の始まりから、長いうねりと中くらいの波の柔らかい網目
- 30〜50 秒で細かい波と、突風への応答が加わる

**パラメータ**: 強さ、月明かり。水深、波の数、波の傾き、露出、各外観の濃さはギャラリーで調整する

**受け入れ基準**

- [x] 網目が実寸で浅い水の底に見える(区切り W1)
- [x] 本文から目をそらさない速さで動く(区切り W2)
- [x] 突風が渡るのが分かる(区切り W2)
- [x] 雲の下、低い太陽、月夜で破綻しない(区切り W3)
- [x] 普段の画面で、浅い水の底で読んでいると感じる(区切り W4)

## 5. 権限とプライバシー

| 権限 | 使うもの | 求める時機 |
|---|---|---|
| 画面収録 | 雨など、背景テクスチャを使うエフェクト | そのエフェクトをオンにしたとき |
| それ以外 | 求めない | — |

アクセシビリティ、入力監視、位置情報の権限は求めない。

守ること【決定】:

- 取り込んだ画面は GPU メモリの中だけで使う。ディスクに書かない。ログに出さない
- ネットワーク通信をしない。解析や計測の送信もしない
- ウィンドウのタイトルやアプリ名を保持しない
- これらはソースコードで確かめられる状態にする(公開リポジトリである意味の一つ)

画面収録に伴う負担(付録 A):

- macOS 15 以降、画面収録の許可はおよそ月に 1 回、再確認のダイアログが出る。アプリ側では止められない
- キャプチャ中はメニューバーに紫のインジケータが出る。押すとアプリ名、画面の縮小表示、「共有を停止」が出る。止めると 13 秒以内に消えた(S4)
- 許可のダイアログが出るのは最初の 1 回だけだった。拒否したあとは、同じアプリが求めてもダイアログは出ず(`tccutil reset` で戻すと、また出た)、システム設定の「画面収録とシステムオーディオ録音」の一覧にオフで載る。ダイアログの「システム設定を開く」は、この一覧を直接開く。オンにすると、次の起動から許可が効く(S4)
- 許可のあと、最初に取り込むときに「システムプライベートウインドウピッカーをバイパスして画面とオーディオに直接アクセスすることが要求されています」の確認が出た(S4)。付録 A の月 1 回の再確認と同じものと見られるが、確かめていない。macOS 27.2.1 での周期も確かめていない
- 取り込み中に許可を取り消すと、「終了するまでは画面の内容を記録できます」のダイアログが出る。ボタンは「終了して再度開く」と「あとで行う」で、「あとで行う」では動いているストリームは止まらなかった(S4、3.9)

拒否のあとはダイアログが出ないので、2 回目からはシステム設定の一覧へ案内する(2.3)。案内の画面は M2 で作る。
- VNC 系アプリ向けに再確認を免除する権限があるが、Apple の承認が要り、Nagi の用途には当たらない見込み

このため、雨は「許可した人だけの追加エフェクト」と位置づける。木漏れ日と苔は権限なしで動く。

## 6. 配布

GitHub でソースコードと dmg を公開する【決定】。Apple Developer Program のチームと証明書は用意済み【決定】。

### 6.1 ビルドと署名

- arm64 のみ、Release 構成
- Developer ID Application で署名、Hardened Runtime を有効、タイムスタンプつき
- App Sandbox を有効にする。`com.apple.security.app-sandbox` だけを付けた Developer ID・Hardened Runtime の版で、S3・S4・S5・S10 が Sandbox なしの版と同じように動いた(S7)
- `LSUIElement` を有効にして Dock に出さない
- ログイン時の起動は `SMAppService.mainApp` で行う。登録すると、ログインのときに 1 回だけ起動し、解除すると起動しなかった(S10)。ログインによる起動は、起動の Apple イベントの `keyAELaunchedAsLogInItem` で見分けられる
- 設定の「ログイン時に起動」は、`status` が `enabled` のときだけオンと表示する。`notRegistered` と `notFound` はオフとして扱う(システム設定で利用者が削除すると `notFound` になる)
- 登録と解除は、利用者が設定を変えたときだけ行う。起動のたびに登録し直さない。利用者がシステム設定で削除しても、アプリからは確認なしに登録し直せてしまうため【仮】
- `requiresApproval` は M0 では一度も出なかった。出たら `SMAppService.openSystemSettingsLoginItems()` でシステム設定のログイン項目へ案内する【仮】

### 6.2 公証と dmg

`scripts/release.sh` が次を一度に行う【仮】。

1. `swift build -c release` の成果物から .app を組み立てる。リソースのバンドルは `Contents/Resources` に置き、内側から順に署名する(`--deep` は使わない。S9)
2. dmg を作り、dmg にも署名する
3. `xcrun notarytool submit … --wait` で公証する
4. `xcrun stapler staple` でチケットを添付する
5. `spctl` と `codesign --verify` で検証する
6. SHA-256 を出力する

GitHub Releases にはタグ `vX.Y.Z` で dmg とハッシュを載せる。当面は手元でリリースする。CI での署名は後回しにする。

### 6.3 秘密の扱い【決定】

- チーム ID、署名 ID、公証用プロファイル名は `Config/Local.xcconfig` と環境変数に置き、コミットしない
- リポジトリには `Local.xcconfig.example` だけを置く
- 公証の認証情報は `notarytool store-credentials` でキーチェーンに保存し、スクリプトはプロファイル名だけを参照する
- 証明書や秘密鍵をリポジトリにも CI にも置かない

## 付録 A 調査メモ(2026-11-18 時点)

実装前に再確認すること。

- **macOS 27 Golden Gate** は 2026-09-14 に公開。Apple silicon 専用で、Intel Mac は macOS 26 まで。
  https://www.macworld.com/article/3139330/macos-27-golden-gate-has-arrived-heres-what-s-new-on-your-mac.html
- **Metal 4** は Apple silicon 専用。Apple の機能表(2026-10-23 版)によると、MetalFX のノイズ除去つきアップスケーリングは GPU ファミリー Apple9 以降、コンピュートでのレイトレーシングは Apple6 以降。Apple9 は M3 世代以降のはず(要確認)。
  https://developer.apple.com/metal/capabilities/
- **画面収録の許可の再確認** は macOS 15 で導入され、およそ月 1 回。macOS 26 でも続いている。無効にする公式の手段はない。macOS 27.2.1 では、許可のあとの最初の取り込みで同じ文言の確認が出た(S4)。周期は未確認。
  https://9to5mac.com/2024/08/14/macos-sequoia-screen-recording-prompt-monthly/
- **Persistent Content Capture の権限** は VNC 系アプリ向けで、Apple への申請が要る。
  https://developer.apple.com/forums/thread/761641
- **`CGWindowListCopyWindowInfo`** は、許可なしでも PID、レイヤー、矩形を返すという報告がある。一方 Apple のフォーラムでは、許可なしで返すキーは文書化されておらず変わりうる、ウィンドウの列挙は ScreenCaptureKit の `SCShareableContent` が今後の方法、と説明されている(こちらは許可が要る)。macOS 27 のベータでは返すキーに変化があったという報告もある。
  https://developer.apple.com/forums/thread/839069
- **`NSGlassEffectView`**(macOS 26 以降)は背後の内容を取り込むという第三者の報告がある。透明度の調整はできず、クリアな表示はアクティブなウィンドウに限られるという報告もある。
  https://github.com/i-am-logger/macos-liquid-glass
  https://github.com/egoist/mygo/issues/598
